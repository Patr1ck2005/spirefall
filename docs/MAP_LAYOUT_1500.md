## 1. 世界换算与全局验算基准

### 1.1 世界与不变的物理量

| 项 | 旧值 | 新值 | 说明 |
|---|---|---|---|
| `WORLD.width` | 1000 | **1500** | ×1.5 |
| `WORLD.height` | 560 | **840** | ×1.5 |
| gravity / jumpGround / jumpAir | 1600 / 620 / 445 | **不变** | 玩家跳跃能力不变 → 垂直层距**不得**跟着 ×1.5 |
| `MAX_JUMPS` | 3 | **不变** | 三段跳链预算 244px |
| `PLAYER_HALF_WIDTH / FOOT_OFFSET / BODY_HEIGHT` | 9 / 4 / 30 | **不变** | 出生/箱位/桶位的 y 约定因此全部不变 |
| `NAV_MAX_RISE / NAV_MAX_GAP` | 115 / 200 | **不变** | bot 导航图边界，新布局全部满足 |

**为什么垂直不 ×1.5**：跳跃高度由 `jumpGround²/(2·gravity)` 决定，与 WORLD 无关。多出来的
280px 垂直空间 = 每图多 2~3 个楼层，而不是更大的跳跃。横向 ×1.5 把对枪线拉长到 ~1500px，
这才是本次 solid 实体墙从每图 1 面 → 2–4 面的根因。

### 1.2 垂直预算（关键验算式）

```
apex_ground = jumpGround² / (2·gravity) = 620² / 3200 = 120.1px
apex_air    = jumpAir²    / (2·gravity) = 445² / 3200 =  61.9px
三段跳链总爬升 = 120.1 + 61.9 + 61.9 ≈ 243.9 ≈ 244px
```

- **相邻层高差 h ≤ 110px**：120.1 > 110，落地余量 10.1px（与现网 fortress 320→210→100 的
  110 台阶同款，物理已验证）。本文档三图主台阶取 **105 或 110**。
- **三段跳应急硬爬**：可连越两个 110 台阶（220 ≤ 244，余 24px）；第三个 110 不行——
  逐层跳仍是常规路线，244 链只是被击退后的逃生手段。
- 空中跳单段 61.9px：只用于半空修正/上 55px 级小台，不承担层间爬升。

### 1.3 水平预算（跳跃落点窗口）

满速 350px/s（MOVE_TUNING 钳制值；地面平衡 ≈340 会到达钳制）。高差 h 的可落地窗口：

```
t_land(h) = ( 620 + √(620² − 3200·h) ) / 1600        （下降沿穿过 h 高度的时刻）
x_max(h)  = 350 · t_land(h)                           （起跳沿到落点沿的最大水平缝）
```

| h (px) | 0 | 15 | 48 | 72 | 78 | 80 | 82 | 90 | 95 | 100 | 105 | 110 |
|---|---|---|---|---|---|---|---|---|---|---|---|---|
| x_max (px) | 271 | 262 | 241 | 222 | 216 | 214 | 212 | 204 | 198 | 191 | **184** | **175** |

- 同高缺口跳（h=0）：人类极限 ≈271px；**bot gapJump 边界 = NAV_MAX_GAP+40 = 240**。
  → 本文档所有地面缺口取 **210 / 220px**：被击退进去必死，主动满速跳稳过（271 > 220）。
- 105 层升的水平缝上限 184px——本文档所有 105/110 层升的水平缝 ≤175px（多数为 0~90）。

### 1.4 坠落/出场规则（沿用 server 现有判定，自动随 WORLD 缩放）

- `server/server.ts:881`：`player.y > WORLD.height + 80` → **y > 920 判 fall 死**（掉出缺口后
  约 0.4s 落到判定线）。三图的地面缺口就是出场区，无坠落伤害、无底面平台。
- 弹丸出界清理 `WORLD.height + 150` → y > 990，同样自动缩放。
- **重生救援契约**：`invulnerable > 0.9` 时 fall 不死、回传 `spawns[index % 4]`——
  因此**每图 spawns[0..3] 必须按「左、左、右、右」排序**（救援落点半场平衡 + 未来分队模式切片都依赖前四位）。
